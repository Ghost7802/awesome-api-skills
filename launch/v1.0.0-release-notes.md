# Awesome API Skills v1.0.0

**Release date:** 2026-06-29  
**Tag:** `v1.0.0`

---

## Highlights

- **100 skills** under `skills/` — each with `SKILL.md`, examples, and `metadata.json`
- **Knowledge graph** in `registry/graph.json` built from skill relationships
- **Monorepo tooling** — validator, generator, registry, SDK, core, and CLI packages
- **Local docs site** via VitePress (`pnpm dev`)
- **28 automated tests** across workspace packages
- **MIT license**

---

## Installation

The CLI is **not published to npm**. Clone and build from source:

```bash
git clone https://github.com/Ghost7802/awesome-api-skills.git
cd awesome-api-skills
pnpm install
pnpm build
```

### Use a skill with an agent

Copy or symlink a skill directory into your project:

```bash
cp -r skills/stripe .skills/stripe
```

Point your agent at `.skills/stripe/SKILL.md`.

### Run the docs site locally

```bash
pnpm dev
```

Open `http://localhost:5173`.

### Run tests

```bash
pnpm test
pnpm lint
pnpm typecheck
```

## Breaking changes

This is the **first public release**. There is no prior stable version to migrate from.

If you were using a private fork or pre-release snapshot:

- Registry default URL is now `./registry` (local path), not a remote placeholder
- Root helper scripts moved under `scripts/generators/`, `scripts/dev/`, `scripts/release/`, `scripts/migrations/`
- AI-generated release reports (`RC2_REPORT.md`, etc.) were removed; see `docs/internal/TRUST_REPORT.md` for the honesty audit

---

## Migration

No migration steps for new users.

For existing fork maintainers:

1. Pull `v1.0.0`
2. Run `pnpm install && pnpm build`
3. Update any custom scripts that referenced root-level `run-validation.js` → `scripts/dev/run-validation-v2.js`
4. Regenerate docs: `node apps/docs/scripts/generate.js`

---

## Known limitations

1. **CLI not on npm** — build from source; no `npm install -g` yet
2. **No public documentation URL** — docs run locally until a site is deployed
3. **CI workflows** target the `main` branch; align your default branch accordingly
4. **Social preview** must be uploaded manually in GitHub repository settings
5. Individual skills may quote vendor marketing in their own `SKILL.md` files; the repository README does not claim vendor endorsement
